## Теоретическая часть

### Что такое обнаружение отказов?

**Failure Detection** — механизм, позволяющий узлам распределённой системы определять, когда другие узлы перестали функционировать. Это критически важный компонент для обеспечения отказоустойчивости.

### Протокол Gossip (Сплетни)

Gossip Protocol — децентрализованный вероятностный протокол, работающий по принципу эпидемического распространения информации:

1. Каждый узел периодически «просыпается»
2. Выбирает `k` случайных соседей (параметр **Fanout**)
3. Обменивается с ними информацией о состоянии кластера
4. Информация распространяется «вирусно»

**Serf** — реализация gossip-протокола от HashiCorp, используемая для обнаружения узлов, выявления сбоев и оркестрации событий.

### Конвергенция

**Конвергенция** — состояние, при котором все живые узлы кластера знают о произошедшем событии (например, об отказе узла). Время достижения конвергенции — ключевая метрика производительности.

### Формула расчёта полосы пропускания

$$Bandwidth = \frac{1}{Interval} \times Fanout \times ActiveNodes \times PacketSize \times Overhead \times 8$$

где:
- $ActiveNodes = N \times (1 - FailurePercent)$
- $PacketSize = 1024$ байт
- $Overhead = 1.2$ (20% накладные расходы заголовков)

### Ключевые параметры

| Параметр | Описание | Влияние |
|----------|----------|---------|
| **Gossip Interval (T)** | Время между раундами обмена (сек) | Меньше T → быстрее обнаружение, выше трафик |
| **Gossip Fanout (k)** | Количество опрашиваемых соседей | Больше k → быстрее сходимость, выше нагрузка |
| **Nodes (N)** | Общее количество узлов | Влияет на масштаб системы |
| **Packet Loss** | Процент потерь пакетов | Снижает вероятность доставки «слуха» |

## Этап 2. Симуляция протоколов

Реализованы три класса-симулятора в файле `simulators.py`:

### 1. SerfSimulator (Gossip)
- Каждый узел выбирает `fanout` случайных соседей
- Учитывается вероятность потери пакета (`packet_loss`)
- Информация распространяется «вирусно» через gossip-сообщения
- Heartbeat-сообщения обновляют таймеры last_heard

### 2. HeartbeatSimulator (Full-mesh)
- Каждый узел пингует **всех** остальных соседей каждый такт
- Самая быстрая сходимость, но квадратичный рост трафика O(N²)

### 3. PingSimulator (Random Probe)
- Каждый узел пингует **одного** случайного соседа
- Низкий трафик, но очень медленное обнаружение отказов

### Механизм обнаружения отказов

Каждый узел отслеживает время последнего получения heartbeat от других узлов. Если `current_time - last_heard[i][j] > timeout` (где `timeout = interval × 3`), узел `i` объявляет узел `j` отказавшим.

- **Трафик:** ≈ 800 — 1100 сообщений за симуляцию

### 3. По приоритизации сообщений

- В конфигурации варианта №21 приоритизация **не дала значительного эффекта**
- Для проявления эффекта требуется более высокая нагрузка или более крупная сеть
- Рекомендуется применять приоритизацию в системах с высокой интенсивностью сбоев

### Итоговое заключение

**Gossip-протокол (Serf) обеспечивает наилучший баланс между скоростью обнаружения сбоев и нагрузкой на сеть.** Heartbeat неприменим для крупных систем из-за квадратичного роста трафика. Ping слишком медленный для практического использования. Приоритизация сообщений о сбоях полезна только в высоконагруженных системах.
